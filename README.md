# Zapret Hosts Updater

Обновление системного `hosts` записями из репозитория
[zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube) **в один запуск**,
вместо ручного копирования через пункт «9. Update Hosts File» в `service.bat`.

Есть две версии: **`update-hosts.bat`** для Windows и **`update-hosts.sh`** для Linux.
Ниже сначала Windows, потом [Linux](#linux).

## Что раздавать (Windows)

Один-единственный файл — **`update-hosts.bat`**. Он самодостаточный: PowerShell-код лежит
внутри него же, после строки `exit /b` (cmd туда не дочитывает). При запуске код
распаковывается во временный файл, выполняется и удаляется.

Куда положить — не важно, пути настраивать не нужно. Удобно рядом с `service.bat` в папке
zapret: тогда адрес списка берётся прямо из `service.bat`, и переезд репозитория ничего
не сломает.

## Файлы репозитория

| Файл | Назначение |
|---|---|
| `update-hosts.ps1` | Исходник для Windows, вся логика. **Править нужно его** |
| `build.ps1` | Собирает `update-hosts.bat` из исходника |
| `update-hosts.bat` | Собранный однофайловый результат — то, что раздаётся |
| `update-hosts.sh` | Версия для Linux, самостоятельный файл, сборка не нужна |

Пересборка после правок:

```bat
powershell -ExecutionPolicy Bypass -File build.ps1
```

`update-hosts.ps1` работает и сам по себе (`powershell -ExecutionPolicy Bypass -File update-hosts.ps1`),
но раздавать удобнее `.bat` — он не упирается в политику выполнения PowerShell.

## Использование

Двойной клик по `update-hosts.bat` → согласиться на UAC → откроется меню:

```
  ZAPRET HOSTS UPDATER
  Автообновление: включено, ежедневно в 04:15
  Следующий запуск: 10.08.2026 4:15:00

  1. Обновить hosts сейчас
  2. Настроить автообновление (ежедневно в заданное время)
  3. Отключить автообновление
  4. Удалить записи zapret из hosts
  5. Открыть папку с hosts
  0. Выход
```

Что делает обновление:

1. Скачивает актуальный список hosts из репозитория (с обходом кэша).
2. Проверяет, что скачалось именно то (иначе — отмена, hosts не трогается).
3. Делает резервную копию текущего `hosts`.
4. Удаляет старый блок zapret и остатки ручных вставок (строки вне блока,
   дублирующие новые домены).
5. Вставляет свежий блок между маркерами.
6. Сбрасывает DNS-кэш.

Записи живут отдельным блоком, поэтому личные строки в `hosts` не затрагиваются:

```
# >>> ZAPRET HOSTS BEGIN >>>
# Источник: ...
# Обновлено: ...
185.199.109.133 objects.githubusercontent.com
...
# <<< ZAPRET HOSTS END <<<
```

Если блок уже актуален — скрипт ничего не пишет и сообщает об этом.

## Автообновление по расписанию

Пункт **2** в меню спрашивает время в 24-часовом формате `Ч:ММ`. Ведущие нули не нужны,
разделителем годится `:`, `.` или `-`. Всё это валидные ответы:

```
3:30    03:30    9:5    23:59    7    0730    12-30
```

При настройке батник **копирует сам себя** в `C:\ProgramData\ZapretHostsUpdater\`, и задача
указывает уже на эту копию. Поэтому исходный файл после настройки можно спокойно
переносить, переименовывать или удалять — автообновление продолжит работать.
Пункт **3** удаляет и задачу, и копию.

Создаётся задача Windows «Zapret Hosts Update», которая:

- запускается **от имени SYSTEM** — UAC при автозапусках больше не появляется,
  и обновление идёт даже если в систему никто не вошёл;
- отрабатывает **пропущенные запуски**: если ПК был выключен в назначенное время,
  обновление выполнится при следующем включении;
- пишет результат в лог `C:\ProgramData\ZapretHostsUpdater\update.log`.

Если рядом с исходным файлом лежал `service.bat`, путь к той папке запоминается в аргументах
задачи — копия в `ProgramData` продолжает брать адрес списка оттуда. Если саму папку zapret
потом перенести, скрипт просто вернётся к адресу репозитория по умолчанию.

Шапка меню (и ключ `-Status`) предупредит, если задача ссылается на исчезнувший файл —
например, когда расписание настраивали старой версией скрипта.

Права администратора нужны только на этапе настройки. Ручной запуск меню будет
запрашивать UAC каждый раз — запись в `hosts` без прав администратора невозможна
в принципе, это ограничение Windows.

### Массовая установка на парк машин

Разложить `update-hosts.bat` по ПК и выполнить на каждом от администратора
(GPO, PsExec, SCCM, скрипт входа — что удобнее):

```bat
update-hosts.bat -Schedule 4:15
```

Ни меню, ни вопросов: задача создаётся, hosts обновится в ближайший назначенный час.
Проверить и снять:

```bat
update-hosts.bat -Status
```

```bat
update-hosts.bat -Unschedule
```

## Резервные копии

`%LOCALAPPDATA%\ZapretHostsUpdater\backups\hosts.ГГГГММДД-ЧЧММСС.bak` — хранятся последние 10.

## Ключи (не обязательны)

Запускать так: `update-hosts.bat -Remove`

| Ключ | Что делает |
|---|---|
| `-Update` | Сразу обновить hosts, без меню |
| `-Schedule <Ч:ММ>` | Включить ежедневное автообновление в указанное время |
| `-Unschedule` | Отключить автообновление |
| `-Status` | Показать состояние автообновления (не требует прав администратора) |
| `-Remove` | Удалить блок zapret из `hosts` и выйти |
| `-Url <адрес>` | Взять список по своему адресу |
| `-KeepConflicts` | Не удалять записи вне блока, даже если они дублируют новые домены |
| `-NoFlushDns` | Не сбрасывать DNS-кэш |
| `-NoPause` | Не ждать Enter в конце (для планировщика задач) |
| `-HostsPath <файл>` | Работать с указанным файлом вместо системного `hosts` (для проверки) |

## Linux

Файл **`update-hosts.sh`** — самостоятельный, собирать ничего не нужно. Логика та же:
тот же блок с теми же маркерами, та же чистка дубликатов, те же проверки скачанного.

```bash
chmod +x update-hosts.sh
./update-hosts.sh
```

Откроется то же меню из пяти пунктов. Root запрашивается через `sudo` один раз при запуске.

### Отличия от Windows-версии

| | Windows | Linux |
|---|---|---|
| Права | UAC | `sudo` (скрипт сам перезапустится) |
| Расписание | Планировщик задач, от `SYSTEM` | systemd-таймер, от `root`; при отсутствии systemd — `cron` |
| Пропущенные запуски | Догоняются | Догоняются (`Persistent=true`); через cron — **нет** |
| Рабочая копия | `C:\ProgramData\ZapretHostsUpdater\` | `/usr/local/sbin/update-hosts.sh` |
| Бэкапы | `%LOCALAPPDATA%\...\backups` | `/var/backups/zapret-hosts-updater/` |
| Лог | `C:\ProgramData\...\update.log` | `/var/log/zapret-hosts-updater.log` |
| Сброс DNS | `ipconfig /flushdns` | `resolvectl flush-caches` или `nscd -i hosts`, если есть |

Ключи — те же, но в unix-стиле:

```bash
./update-hosts.sh --update
```

```bash
./update-hosts.sh --schedule 4:15
```

```bash
./update-hosts.sh --status
```

```bash
./update-hosts.sh --unschedule
```

Ещё есть `--remove`, `--url <адрес>`, `--keep-conflicts`, `--no-flush-dns`, `--no-pause`,
`--hosts-path <файл>`, `--help`.

Запись в `/etc/hosts` идёт через `cat`, а не `mv` — так сохраняются inode, права и владелец.
Это важно в контейнерах и там, где `/etc/hosts` подмонтирован. Если запись не проходит,
проверьте атрибут immutable: `lsattr /etc/hosts`.

Зависимости: `bash`, `awk`, `sed`, `grep` и `curl` либо `wget` — всё это есть в любом
дистрибутиве из коробки.

## Если антивирус ругается

Однофайловая сборка распаковывает свой PowerShell-код в `%TEMP%` — редкие эвристики это
не любят. Тогда используйте `update-hosts.ps1` напрямую:

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File update-hosts.ps1
```

## Если не сработало

- **«Не удалось записать hosts»** — почти всегда антивирус (Kaspersky, Dr.Web, Avast) держит
  защиту hosts-файла. Отключите её и повторите.
- **Ошибка скачивания** — репозиторий на GitHub недоступен без обхода блокировок;
  запустите zapret (`general.bat`) и повторите.
